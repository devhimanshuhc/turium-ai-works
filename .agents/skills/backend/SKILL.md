# Backend Conventions (FastAPI)

## Layout

```
apps/server/
├── config.py             # Settings (pydantic-settings) — the only place env is read
├── alembic.ini
├── migrations/           # Alembic migrations (autogenerated from models, then reviewed)
├── app/
│   ├── main.py           # App wiring: logging, middleware, exception handlers, routers. Nothing else.
│   ├── core/             # logging.py (JSON logs + request_id), errors.py (AppError + handlers), middleware.py
│   ├── db/               # base.py (Base, mixins, string_enum), session.py (engine, get_session)
│   ├── routers/          # HTTP layer — one file per resource (ingest.py, items.py, query.py)
│   ├── schemas/          # Pydantic request/response models — one file per resource
│   ├── services/         # Business logic — ingestion, chunking, retrieval, answering
│   ├── clients/          # LLM + embedding providers (OpenAI, Gemini), retry, web fetcher
│   └── models/           # SQLAlchemy models — one file per table group
├── tests/                # pytest — conftest.py provides `api` (with fakes) and `client`
├── evals/                # golden dataset, corpus, LLM-judge eval runner (`pnpm --filter server eval`)
├── package.json          # Turbo entry points: dev, test, typecheck, lint:fix
└── pyproject.toml        # uv-managed dependencies, ruff config
```

Keep every file small and single-purpose; split before a file becomes a god file.

---

## Request flow

```
router  →  service  →  client / storage
```

- **Routers** parse input (via schemas), call one service function, and map domain errors to HTTP status codes. No business logic, no SQL, no OpenAI calls.
- **Services** hold the logic and are plain functions or small classes with injected dependencies, so tests can swap them.
- **Clients** wrap one external system each and set explicit timeouts.

Use FastAPI `Depends` to provide services/clients to routers so tests can override them with `app.dependency_overrides`.

## Schemas & validation

- Every endpoint declares `response_model`. Never return raw dicts from storage.
- Validate at the edge: `Field(min_length=..., max_length=...)`, `HttpUrl`, `Literal`/`Enum` for source types.
- Name models after intent: `IngestRequest`, `ItemResponse`, `QueryRequest`, `QueryResponse`, `SourceCitation`.
- Use snake_case in Python. Keep JSON field names stable — the frontend types in `apps/web/src/types/` mirror them.

## Errors & status codes

Raise the `AppError` subclasses from `app/core/errors.py` (subclass them for specific cases, e.g. `class UrlFetchError(UpstreamError)`). The global handlers in `register_exception_handlers` produce the response, so routers and services never build error responses themselves:

| Situation | Status |
|---|---|
| Invalid body (Pydantic) | 422 (automatic) |
| Semantically bad input (e.g. URL returned no readable text) | 400 |
| Resource not found | 404 |
| Duplicate (e.g. knowledge base name taken) | 409 |
| Upstream failure (URL fetch, embeddings, LLM) | 502 |
| Required dependency not configured (e.g. missing API key) or database unreachable | 503 |

Error bodies use FastAPI's `{"detail": "<human readable message>"}` shape — the web `ApiClient` reads `detail`.

## Config

- Add every setting to `Settings` in `config.py` with a sensible default (secrets default to empty and are checked at use).
- Mirror each new variable in `apps/server/.env.example`.
- Import `config` from `config` — never read `os.environ` directly.

---

## Logging

- Use `logger` from `app.core.logging`. Never `print`. Every line is JSON and includes the current `request_id`.
- Log events with context: `logger.info("item ingested", extra={"item_id": ..., "source_type": ..., "chunks": ...})`.
- Log latency for embedding, retrieval and LLM calls. Never log API keys or full document text.

## RAG pipeline

Each stage is its own module; keep it that way.

| Stage | Module |
|---|---|
| File text extraction | `services/ingestion/extractors.py` |
| Parent (≤2000) / child (≤400, 80 overlap) chunking | `services/ingestion/chunking.py` |
| Contextual sentence per child (fast model, one call per parent) | `services/ingestion/contextualizer.py` |
| Fetch → chunk → contextualise → embed → store, status updates | `services/ingestion/pipeline.py` |
| Hybrid search (pgvector + tsvector, RRF, lift to parents) | `services/retrieval.py` |
| Follow-up rewriting | `services/rag/planner.py` |
| Prompts (answer, planner, judge) | `services/rag/prompts.py` |
| Citation check + LLM-as-judge groundedness | `services/rag/guardrails.py` |
| Streams events, persists messages | `services/rag/orchestrator.py` |

- Provider clients live in `app/clients/` behind `LLMClient` (`generate_json`, `stream_text`, tiers `fast`/`answer`) and `Embedder` (`embed_documents`, `embed_query`, `model`). Pick them via `app/clients/providers.py`; never import an SDK in a service.
- Raise `LLMError` / `EmbeddingError` (502) from clients. Degrade gracefully where the stage is optional (contextualiser, planner, judge) and log a warning.
- Every chunk stores `embedding_model`; retrieval only compares vectors from the active model.
- Record the reasoning behind any constant you change in `docs/reference/design-decisions.md`, and rerun `pnpm --filter server eval`.

## Database

- Models live in `app/models/`, one file per table group, all exported from `app/models/__init__.py` (Alembic reads `Base.metadata` from there).
- UUID primary keys (`UuidPrimaryKeyMixin`), `created_at`/`updated_at` (`TimestampMixin`), enums stored as lowercase strings (`string_enum`).
- Get a session with `Depends(get_session)`; services receive the `AsyncSession` as an argument.
- Schema change → `pnpm --filter server db:revision "<message>"`, review the file, `pnpm db:migrate`. `uv run alembic check` must report no pending changes.

---

## Testing

- `pnpm --filter server test` (or `uv run pytest` inside `apps/server`).
- API tests use the `api` fixture (httpx + ASGI against a real `knowledge_inbox_test` Postgres database, truncated after each test) with `FakeLLM`, `FakeEmbedder` and `FakeFetcher` from `tests/fakes.py`. Tests must not hit the network or a real provider.
- Cover: validation errors, happy paths for `/ingest`, `/items`, `/query`, and upstream failures mapping to the right status code.
- Unit-test the chunker and similarity ranking directly.

---

## Tooling

- Dependencies: `uv add <pkg>` / `uv add --dev <pkg>` from `apps/server`.
- Lint/format: `uv run ruff check --fix . && uv run ruff format .` (also run by `pnpm lint:fix`).
- Types: `uv run mypy app config.py` (also run by `pnpm typecheck`).
